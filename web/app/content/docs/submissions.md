## 解答を提出する {#submit}

![問題ページの提出欄。①言語、②ソースコード、③サンプル検証、④提出する](/images/docs/submit-form.png)

1. ①で言語を選びます。
2. ②にソースコードを入力します。
3. ④「提出する」を押します。

- 提出にはログインとプロフィールの登録が必要です。
- 提出すると提出結果の画面に移り、採点が終わるまで結果を自動で更新します。
- 言語ごとの仕様は[使える言語と実行環境の仕様](/docs/languages)にまとめています。

続けて使える回数には上限があります。

| 操作 | 上限 |
| --- | --- |
| 提出する | 60秒に2回 |
| [サンプル検証](#sample-check) | 60秒に3回 |
| [コード実行](#code-run) | 60秒に3回 |

## サンプル検証 {#sample-check}

提出欄の③「サンプル検証」は、提出する前にサンプルケースだけで判定します。

- 使うのは、作問者がサンプルケースに指定したテストケースです。問題文に書かれた入出力例は使いません。
- 結果は提出欄の下に、ケースごとの入力、期待される出力、実際の出力として表示します。
- 結果は本人だけが見られ、提出一覧や順位には入りません。

## コード実行 {#code-run}

[コード実行](/run)では、問題を選ばずに、言語、ソースコード、標準入力を渡して出力を確かめられます。

| 項目 | 上限 |
| --- | --- |
| 実行時間 | 5秒 |
| メモリ | 512 MiB |
| 標準入力 | 1 MiB |

- 利用にはログインとプロフィールの登録が必要です。
- 結果は提出一覧や順位に入りません。
- コード実行の:AC:は、プログラムが正常に終了したことだけを表します。出力は何とも比べません。

## 判定結果の種類 {#verdicts}

| 結果 | 意味 |
| --- | --- |
| :AC:<br>正解 | すべてのテストケースで正しい出力を返しました。 |
| :WA:<br>不正解 | 出力が期待される出力と一致しませんでした。 |
| :TLE:<br>実行時間超過 | 実行時間制限を超えました。 |
| :MLE:<br>メモリ超過 | メモリ制限を超えました。 |
| :OLE:<br>出力超過 | 出力が大きすぎました。 |
| :RE:<br>実行時エラー | プログラムが異常終了しました。 |
| :CE:<br>コンパイルエラー | コンパイルまたは実行前の構文検査に失敗しました。 |
| :JE:<br>採点できませんでした | 判定コードの失敗やジャッジの障害で、採点を完了できませんでした。 |
| :WJ:<br>ジャッジ中 | 採点の順番を待っているか、コンパイルしています。 |

## 採点の進み方 {#judging}

- テストケースは登録順に実行します。途中で正解以外の結果が出ても、残りのケースを続けて実行します。
- :TLE:のケースが2件になると、残りのケースは実行せずに「未実行」とします。
- コンパイルに失敗すると:CE:になり、テストケースは実行しません。
- 提出全体の結果は、登録順で最初に正解にならなかったケースの結果です。たとえば3件目が:WA:、5件目が:TLE:なら、提出全体は:WA:です。
- 提出結果の「実行時間」と「メモリ使用量」は、各テストケースのうち最も大きい値です。

## 出力の比べ方 {#comparison}

通常判定では、出力を空白文字（スペース、タブ、改行など）で区切り、語の並びが期待される出力と一致するかを比べます。

| 違い | 扱い |
| --- | --- |
| 行末の空白、最後の改行の有無、連続する空白 | 同じ出力として扱います。 |
| 大文字と小文字（`Yes` と `YES`） | 別の出力です。 |
| 数の書き方（`1.0` と `1`） | 別の出力です。 |

誤差を認める問題や答えが複数ある問題は、作問者が[誤差ジャッジ](/docs/checkers#error-judge)や[スペシャルジャッジ](/docs/checkers)で判定します。

## 提出を見られる人 {#visibility}

![問題ページのタブ。①自分の提出、②すべての提出](/images/docs/problem-tabs.png)

- 自分の提出は①「自分の提出」で見られます。コンパイルエラーの内容も確認できます。
- 公開中の問題への提出は、②「すべての提出」で誰でも見られます。
- コンパイルエラーの内容とテストデータは、ほかの人には表示しません。

次の提出は、ほかの人には公開しません。

- サンプル検証
- 問題を公開する前に、作者とテスターがした提出
- 終了前のコンテストでの提出（[コンテストのルール](/docs/contest-rules#visibility)）
- 解説の公開前の、定期便の新作への提出（[定期便](/docs/featured#solve)）

## 問題が更新されたとき {#rejudge}

提出は、受け付けた時点の問題の内容で採点します。
あとから問題が更新されても、問題の作者やテスターがリジャッジ（再採点）するまで結果は変わりません。
リジャッジ中の提出は:WJ:になり、新しい結果は順位表と正解者数にも反映されます。
