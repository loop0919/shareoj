## 解答を提出する {#submit}

問題ページの「問題文」の下に提出欄があります。
提出にはログインとプロフィールの登録が必要です。

![問題ページの提出欄。①言語、②ソースコード、③サンプル検証、④提出する](/images/docs/submit-form.png)

①で言語を選び、②にソースコードを入力して、④「提出する」を押してください。
言語ごとのバージョンや書き方は、[使える言語と実行環境の仕様](/docs/languages)にまとめています。

提出すると、提出結果の画面に移ります。
画面の結果は、採点が終わるまで自動で更新されます。

「提出する」は90秒間に2回まで、③「サンプル検証」は60秒間に3回まで使えます。
2つの回数は別々に数えます。
上限に達したときは、次に提出できるまでの秒数を表示します。

## サンプル検証 {#sample-check}

「サンプル検証」は、作問者がサンプルケースに指定したテストケースだけで判定します。
問題文に書かれた入出力例は使いません。
サンプルケースがない問題では、ボタンを押せません。

結果は提出欄の下に表示し、ケースごとに入力、期待される出力、実際の出力を並べます。
長い入出力は先頭部分だけを表示します。
インタラクティブ問題では、入出力の代わりにケースごとの対話の記録を表示します。

サンプル検証の結果は、本人だけが見られます。
提出一覧、正解者数、コンテストと定期便の順位には含めません。
コードか言語を変えると、表示中の結果は消えます。

## 判定結果の種類 {#verdicts}

| 結果 | 意味 |
| --- | --- |
| :AC:<br>正解 | すべてのテストケースで正しい出力を返しました。 |
| :WA:<br>不正解 | 出力が期待される出力と一致しませんでした。スペシャルジャッジでは、検証コードが不正解と判定しました。 |
| :TLE:<br>実行時間超過 | CPU時間が実行時間制限を超えたか、経過時間が上限を超えました。 |
| :MLE:<br>メモリ超過 | メモリ制限を超えたため、プログラムを停止しました。 |
| :OLE:<br>出力超過 | 標準出力が16 MiB、または標準エラー出力が64 KiBを超えました。 |
| :RE:<br>実行時エラー | プログラムが0以外の終了コードで終了したか、シグナルで停止しました。 |
| :CE:<br>コンパイルエラー | コンパイルまたは実行前の構文検査に失敗しました。 |
| :JE:<br>採点できませんでした | 判定コードの失敗やジャッジの障害で、採点を完了できませんでした。 |
| :WJ:<br>ジャッジ中 | 採点の順番を待っているか、コンパイルしています。 |

経過時間の上限は、実行時間制限の3倍に1秒を足した長さです。
テストケースごとの結果では、実行しなかったケースを「未実行」と表示します。

## 採点の進み方 {#judging}

採点は、コンパイルとテストケースの実行の順に進みます。
コンパイルに失敗するとCEになり、テストケースは実行しません。

テストケースは登録順に実行します。
途中で正解以外の結果が出ても、残りのケースを続けて実行します。
ただし、TLEのケースが2件になった時点で、残りのケースは実行せずに「未実行」とします。
サンプル検証では、TLEが出てもすべてのケースを実行します。

採点中は、結果の欄に「3/10」のように終わったケースの数を表示します。
正解以外のケースが出ると「WA 3/10」のように、最初に出た結果を添えます。

提出全体の結果は、登録順で最初に正解にならなかったケースの結果です。
たとえば、3件目がWA、5件目がTLEなら、提出全体はWAです。
すべてのケースが正解ならACです。

## 出力の比べ方 {#comparison}

通常判定では、出力と期待される出力を空白文字（スペース、タブ、改行など）で区切り、語の並びが一致するかを比べます。
行末の空白、最後の改行の有無、連続する空白の違いは結果に影響しません。

区切られた語どうしは、1文字ずつ完全に一致する必要があります。
`Yes` と `YES`、`1.0` と `1` は別の出力として扱い、小数の誤差も認めません。
誤差を認める問題や答えが複数ある問題は、作問者が[スペシャルジャッジ](/docs/checkers)で判定します。

## 実行時間とメモリ {#usage}

提出結果の「実行時間」と「メモリ使用量」は、各テストケースのうち最も大きい値です。
実行時間はプログラムと子プロセスのCPU時間で、ケースごとの表には経過時間も表示します。

メモリ使用量には、実行環境や子プロセスが使うメモリも含みます。
提出結果では1 MB＝1,000,000バイトで表示し、問題ページのメモリ制限は1 MiB＝1,048,576バイトで表示します。

## 提出を見られる人 {#visibility}

自分の提出は、コンパイルエラーの内容を含めてすべて確認できます。

![問題ページのタブ。①自分の提出、②すべての提出](/images/docs/problem-tabs.png)

問題ページの①「自分の提出」と、マイページの「提出履歴」から開いてください。
提出履歴には、最新の50件を表示します。

公開中の問題への提出は、ログインしていない人を含めて誰でも見られます。
見られるのは、ソースコード、判定結果、テストケースごとの結果、実行時間、メモリ使用量です。
コンパイルエラーの内容とテストデータは、ほかの人には表示しません。
問題ページの②「すべての提出」に、公開されている提出が並びます。

次の提出は、ほかの人には公開しません。

- サンプル検証
- 問題を公開する前に、作者とテスターがした提出
- 終了前のコンテストでの提出（詳しくは[コンテストのルール](/docs/contest-rules#visibility)）
- 解説の公開前の、定期便の新作への提出（詳しくは[定期便](/docs/featured)）

## 問題が更新されたとき {#rejudge}

提出は、受け付けた時点のテストケース、制限、判定方法で採点します。
あとから問題が更新されても、それだけでは採点済みの結果は変わりません。

問題の作者とテスター、運営は、提出をリジャッジ（再採点）できます。
リジャッジした提出は、その時点で保存されている問題の内容で採点し直すので、結果が変わることがあります。
新しい結果は、コンテストの順位、正解者数、定期便の順位表にも反映されます。
採点し直している間、その提出はWJになります。
提出結果の画面には、リジャッジした日時を表示します。

## ジャッジのメンテナンス中 {#maintenance}

ジャッジのメンテナンス中は、画面の上部にお知らせを表示します。
この間は提出とサンプル検証ができず、提出欄の「言語」も空になります。
入力したソースコードは提出欄に残ります。
