## 作問画面を開く {#start}

![ヘッダーの作成メニュー。①作成、②新規問題](/images/docs/create-problem.png)

ログインしてから、ヘッダーの①「作成」で②「新規問題」を選びます。
マイページの「自分の問題」にある「新規問題」からも始められます。

![作問画面。サイドバーの①問題文から⑤問題管理までと、⑥保存](/images/docs/problem-editor.png)

作問画面では、サイドバーの①〜⑤で編集する項目を切り替えます。

| 項目 | 設定する内容 |
| --- | --- |
| ①問題文 | タイトル、難易度、実行時間制限、メモリ制限、タグ、本文 |
| ②テストケース | 採点に使う入力と期待される出力 |
| ③生成・検証・判定 | テストケースを作るコード、入力の検証、判定方法 |
| ④解説 | 問題ページの「解説」タブに表示する文章 |
| ⑤問題管理 | 公開できるかの確認、テスターの招待、リジャッジ、問題の削除 |

## 問題文と設定 {#statement}

タイトルは120文字まで、本文と解説はそれぞれ100,000文字までです。
本文と解説はMarkdownで書きます。
書き方は[Markdown と数式の書き方](/docs/markdown)を見てください。

実行時間制限は100〜5,000ミリ秒の範囲で、100ミリ秒単位で設定します。
メモリ制限は64〜512 MiBです。
難易度はLv.1〜10から選びます。
選び方は[難易度の目安](/docs/difficulty)を参考にしてください。
タグは5個まで付けられます。

## テストケース {#tests}

![テストケースの画面。①ファイルから一括追加、②サンプルケースにする、③サンプルを問題文に追加](/images/docs/problem-tests.png)

①で、手元のファイルをまとめて登録できます。
②を有効にしたケースは、解く人の「サンプル検証」で使います。
③を押すと、サンプルケースの入出力を本文に書き足します。

テストケースをコードで作る方法は[入出力生成と入力検証の使い方](/docs/generator)、判定方法の設定は[判定方法の設定](/docs/checkers)で説明しています。

## 保存する {#save}

公開しておらず、コンテストにも登録していない問題は、編集すると自動で保存します。
「保存」ボタン（[作問画面](#start)の⑥）かCtrl+S（macOSでは⌘S）でも保存できます。
保存しても、問題は公開されません。

保存した問題は、マイページの「自分の問題」に並びます。
別の端末からも編集を再開できます。

公開中の問題とコンテストに登録した問題は、自動では保存しません。
「保存」を押すと、その時点の内容が公開中の問題やコンテストの出題内容に反映されます。

新しい問題を初めて保存するときに、作成枠を1件使います。
作成枠は最大20件で、2時間ごとに1件ずつ回復します。
問題、コンテスト、記事の作成枠は別々に数えます。

## 公開できるかを確かめる {#readiness}

![問題管理の状態。①判定の結果、②足りない項目を開くボタン](/images/docs/problem-status.png)

「問題管理」の①「状態」に、保存済みの内容で公開やコンテスト、定期便に出せるかを表示します。
足りない項目は、②のボタンから開いて直せます。

| 出し先 | 必要なもの |
| --- | --- |
| 公開 | タイトル、本文、難易度。スペシャルジャッジかインタラクティブでは、判定コードと、ジャッジで使える言語 |
| コンテスト | 公開の条件に加えて、テストケース1件以上 |
| 定期便 | コンテストの条件に加えて、解説 |

テストケースがなくても公開はできますが、テストケースが1件もない問題には提出できません。

## 公開する {#publish}

![問題一覧の①問題投稿と、投稿画面の②投稿する問題、③公開するタイミング、④投稿](/images/docs/problem-post.png)

問題一覧の①「問題投稿」を押し、②で問題、③で公開のタイミングを選んで、④「投稿」を押します。
③で「日時を指定して予約」を選ぶと、予約した時点の保存内容を、指定した日時に公開します。
予約したあとに問題を編集した場合は、「予約を更新」で公開する内容を差し替えてください。
予約は「問題管理」や「自分の問題」から変更、取り消しできます。

コンテストに登録した問題は投稿できません。
コンテストの終了後に自動で公開します。

公開する前でも、作者とテスターは問題ページを開いて提出できます。
公開前の提出は、問題を公開したあとも公開しません。

## 公開したあと {#after-publish}

公開中の問題を編集して「保存」すると、すぐに公開内容に反映します。
保存できるのは、公開の条件を満たしている場合だけです。
受け付け済みの提出は、提出した時点の内容で採点しているため、そのままでは結果は変わりません。
新しい内容で採点し直すには、[リジャッジ](#rejudge)してください。

![問題管理の①非公開に戻すと②問題を削除](/images/docs/problem-unpublish.png)

「問題管理」の①「非公開に戻す」で、問題を非公開に戻せます。
一度公開した問題は、非公開に戻しても定期便には応募できません。

②「問題を削除」で、問題を削除できます。
公開中の問題も削除できますが、コンテストに登録した問題は削除できません。

## リジャッジする {#rejudge}

テストケースや判定方法を直したあと、受け付け済みの提出を新しい内容で採点し直せます。

![問題管理の①すべてリジャッジ](/images/docs/problem-rejudge.png)

「問題管理」の①「すべてリジャッジ」を押すと、この問題へのすべての提出が対象になります。

![すべての提出の一覧。①提出のチェックボックス、②リジャッジ](/images/docs/rejudge-list.png)

問題ページとコンテストの問題ページにある「すべての提出」「自分の提出」では、①で提出を選ぶと②「リジャッジ」が表示され、選んだ提出だけをリジャッジできます。
提出結果の画面では、「この提出をリジャッジ」でその提出だけをリジャッジできます。

リジャッジは保存済みの内容で採点するので、先に「保存」してください。
採点中の提出、サンプル検証、現在使えない言語の提出は対象になりません。
新しい提出の採点を優先するため、リジャッジは空いているジャッジで順に進みます。
件数が多いと、終わるまで時間がかかります。

リジャッジできるのは、問題の作者とテスター、運営です。

## テスターを招く {#testers}

![問題管理のテスターリンク。①リンクを発行、②リンクをコピー](/images/docs/problem-testers.png)

「問題管理」の①「リンクを発行」を押すと、招待リンクを作れます。
②でコピーしたリンクを開いた人が「許可する」を押すと、その問題のテスターになります。

テスターは、非公開の問題文、解説、テストケースを閲覧し、提出できます。
問題の編集、削除、リジャッジもできます。
公開予約、コンテストへの登録、定期便への応募は、作者だけができます。
テスターの名前は問題ページに表示します。

## 解説とユーザー解説 {#editorials}

作問画面の「解説」に書いた文章は、問題ページの「解説」タブに表示します。
定期便に応募するには解説が必要です。

ほかのユーザーが記事を書くときに「解説する問題」に問題を指定すると、その記事が問題ページの「ユーザー解説」に並びます。
ユーザー解説を付けられるのは、解説が公開されている問題だけです。
