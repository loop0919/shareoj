# ADR 0042: 配信モードで、スタッフ向けの画面を既定で閉じる

- 状態：Accepted（2026-11-26に公開）
- 決定日：2026-11-24
- 範囲：Web（設定、ヘッダー、Webサーバーの`privateAPI`、閉じたページ）。APIとデータベースは変えない。

## 背景

コンテストのスタッフ（作成者、問題の作者、テスター）のアカウントで順位表を映して実況すると、映してはいけない画面が配信に出るおそれがある。
マイページや未公開の問題の作問画面を開いてしまう。
開催中に、全員分の提出一覧を開いたり、順位表の得点から他の人の提出を開いたりする。

配信中に別のブラウザや端末でリジャッジなどの運営の操作をするので、アカウントや利用者全体には制限をかけたくない。

## 決定

### 状態はブラウザごとのCookieに持つ

Cookie `openoj-streaming`に持つ。値は`1`で、オフのときはCookieを消す。
期限は1年、`SameSite=Lax`、`path=/`とし、画面のコードから読み書きできる。
配信モード中は、Webサーバーがページの応答でCookieを設定し直すので、期限は最後にページを開いたときから1年になる。
Webサーバーが要求ごとに読むので、最初に返すHTMLから配信モードの表示になる。
ログアウトしても消さない。

配信モードの切り替えは、設定の項目「配信モード」のスイッチ「このブラウザを配信モードにする」で行う。
切り替えるとページを読み込み直す。オフにするときだけ確認を挟む。
ヘッダーには、配信モード中だけ「配信モード」の印を出す。印からも、未ログインのままオフにする確認を開ける。

同じブラウザのほかのタブは、`BroadcastChannel`で知らせを受けたときのほか、読み込んだとき、戻る・進むのキャッシュから戻ったとき、表示に戻ったとき、画面を移るときにもCookieを見る。
変わっていれば、画面を覆って読み込み直す。
覆いは閉じられず、閉じても出し直し、そのあいだ画面の中身も隠す。

### 既定で閉じ、通す呼び出しだけを選ぶ

セッションを付けてAPIを呼ぶ通信は、`web/server/utils/private-api.ts`の`privateAPI`を通る。
配信モードの要求では、呼び出し側が「配信モードでも使う」と明示したものだけを通す。
それ以外は、APIを呼ばずに403と`data: { code: 'streaming_mode' }`で断る。
明示を書き忘れると閉じる側に倒れる。

通すのは、ログイン中かどうか、ヘッダーの名前とアイコン、提出とサンプル検証、ログインと登録、自分の提出の詳細、コード実行、解いた問題の印、お気に入りと難易度の投票、問題ページの「自分の提出」、コンテストのページである。
下書き、作問、管理、通知、質問、プロフィールの更新などは閉じる。

公開の内容とスタッフ向けの内容を出し分けている経路は、閉じたときに公開の経路へ落ちる。

### スタッフには公開の内容を返す

コンテストのページ（`/api/contests/**`）は、セッションを使う経路になる要求（コンテスト本体、問題、提出、`mine`）に限って、見ている人がスタッフかどうかを先に確かめる。
スタッフなら、未ログインの人と同じ公開の経路で答える。`mine`は403で断る。
スタッフでないと確かめられたときだけ、セッション付きで読む。確かめに失敗したときは失敗として返す。
順位表（`live=1`を含む）と解説は、確かめずに公開の経路で答える。

そのため、スタッフは自分のコンテストでは、配信モード中は提出できない。

自分の提出の詳細は、判定コードの診断と、生成のジョブの出力を落としてから返す。
診断が残るのは、対話型と2ステップの問題のサンプル検証だけである。

### 閉じたページ

次のページは、中身を出さず、「配信モード中は表示できません」の画面を出す。

- `/my`の下のページ（`/my/settings`と`/my/submissions/{id}`を除く）
- 作問、投稿、応募、オンボーディングのページ
- コンテストのチームのページ

閉じるかどうかは、URLの文字列ではなく、当たったルートで決める。
大文字やパーセントエンコードで綴りを変えても閉じる。
新しく`/my`の下に足したページも、何もしなくても閉じる。

ミドルウェアが閉じたページへの移動を止めるのに加えて、ページを描く場所も、閉じたルートではページの代わりに閉じた画面を描く。
エラーの状態が消えても、閉じたページは描かれない。
閉じた画面の「ホームへ戻る」は、ホームのページを新しく読み込む。

公開ページに置かれたスタッフ向けの部品は、配信モード中は描かないか、通信を出さない。
参加登録の部品があった場所には「配信モード中は参加登録できません。」と出す。
参加している人には、開始前の「参加登録を取り消す」も出さない。

## 代替案

- **アカウント単位の設定にする**：配信中に別のブラウザや端末で運営の操作ができなくなる。
- **ログアウトと同じ見え方にする**：セッションは残せるが、提出、自分の提出、コード実行が使えなくなる。小さく作れる案だったが、これらを配信モードでも使いたいので採らなかった。
- **APIで権限を落とす**：APIはスタッフかどうかを多くのデータベース問い合わせの中で決めているので、「スタッフとして扱わない」指定を認可の処理に広く通すことになる。
- **画面を1つずつ隠す**：既定を閉じにしないので、あとから足した画面は、一覧に足し忘れると映ってしまう。

## 影響

- 配信モードは、スイッチを入れたブラウザで、うっかり映してしまうことを防ぐためのものである。認可ではない。
  APIは変わらないので、CLIやほかのブラウザからの操作には影響しない。
- 配布はWebだけでよい。
- `privateAPI`で通す呼び出しを増やすときは、配信モードで見せてよいかを呼び出しごとに判断する。
- スタッフは、配信モード中は自分のコンテストで提出できない。試すときは、配信モードを入れていないブラウザを使う。
