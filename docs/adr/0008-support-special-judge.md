# ADR 0008: 作問者の検証コードによるスペシャルジャッジを提供する

- 状態: Accepted（スコアファイルの扱いは[ADR 0025](0025-score-partially-with-test-groups.md)で一部変更）
- 決定日: 2026-09-13

## 背景

構築問題など、複数の正解が存在する問題では、期待出力との空白区切りの比較だけでは正誤を判定できない。
作問者が条件をコードで記述できるようにし、yukicoder形式の検証コードを移植しやすくする。

## 決定

問題ごとに通常判定かスペシャルジャッジを選び、後者では検証コードと言語を下書きに保存する。
検証コードは提出で現在選べる言語をすべて利用でき、提出側の言語とは独立して選ぶ。
言語一覧、コンパイルコマンド、実行環境は提出用のものを共用する。

提出プログラムが正常に終了したケースについて、次の形式で検証コードを実行する。
期待出力は空ファイルでもよい。

```sh
checker 入力ファイル 期待出力ファイル 提出ソースファイル スコアファイル < 提出出力
```

検証コードの終了コード0をAC、それ以外の終了コードとシグナルによる異常終了をWAとする。
これにより、作問者は`assert`で不正解を表現できる。
検証コード自身のバグがWAになることを許容する。
コンパイル失敗、時間制限、メモリ制限、出力制限の超過と実行基盤の障害はJEとする。
提出側のCE、TLE、MLE、OLE、REを検証コードで上書きしない。

検証コードも信頼できないプログラムとして、提出とは別の隔離環境でコンパイルして実行する。
コンパイル成果物を別々に保持し、各ケースの環境を破棄してから次のケースへ進む。
期待出力と検証コードを提出環境へ公開せず、検証コードの計算資源を提出の計測値へ加算しない。

公開操作は検証コードを含む問題設定を固定する。
提出受付では、公開版（未公開なら所有者の下書き）の検証コードとテストケースを同一のDB操作で複製し、実行環境のdigestとともに保存する。
後の問題編集は受付済みの提出へ影響しない。
非公開の問題で試験提出を行えるようにし、公開済みの問題への提出は公開版を使う。

検証コードの診断ログには、非公開の入力や期待出力が含まれ得る。
保存するログ量を制限し、問題作成者による自身の提出詳細の取得時だけ返す。
提出一覧と、問題作成者以外への応答には含めない。

## 代替案

終了コード1だけをWA、それ以外をJEとすれば異常終了を区別できるが、`assert`での判定や既存コードの移植を妨げるため採用しない。
検証言語をC++だけに限定する案も、現在提出できる言語を検証にも使うという要件を満たさない。

## 影響

検証コードのコンパイルとケース実行の分だけ採点時間が増える。
実行上限と採点全体の予算は[スペシャルジャッジ仕様](../judge/special-judge.md)で管理する。
DBのJSONスナップショットを拡張するため、既存問題の通常判定を維持したまま追加できる。

yukicoderとの互換範囲は引数、標準入力、非ゼロ終了によるWAである。
対話形式、スコア集計、QLE、testlibの追加提供は今回の対象に含めない。
第4引数のスコアファイルは書き込み可能な空ファイルを渡し、内容を採点に使わない。
終了コード100もWAとする。
