# ADR 0017: 記事をユーザー解説として問題に紐付ける

- 状態：Accepted
- 決定日：2026-10-11
- 範囲：記事と問題の紐付け、問題ページ・記事ページ・コンテストの解説一覧での表示、問題の作者への通知

## 背景

問題の解説タブには、作問者が書いた公式解説しか載らない。
別解や詳しい説明を記事に書いても、問題ページからはたどれなかった。
記事は下書きと公開スナップショットを分けて保存していて、問題とのつながりは持っていなかった。

## 決定

### 記事の作者が、解説する問題を指定する

記事エディターで、その記事が解説する問題を最大30問まで指定する。
コンテストの全問をまとめて解説する記事も、1本の記事として扱える。
問題の作者の承認は求めない。誰でも、公開中の問題にユーザー解説を付けられる。

### 問題の一覧は記事の公開内容に含める

指定した問題は`blog_posts.problem_ids`に下書きとして保存し、「公開する」「公開内容を更新」で`published_problem_ids`へ写す。
タイトル・本文と同じく、保存しただけでは公開ページに反映しない。
保存APIで`problemIds`を省略したときは一覧を変えない。

### 公式解説を誰でも読める問題だけを指定できる

保存時に受け付けるのは、公開されていて、定期便の解説の解禁前でもない問題だけにする。
開催中のコンテストの問題は、終了後に自動公開されるまで指定できない。
表示時にも同じ条件で絞り込むので、後から非公開になった問題からは記事へのリンクが消える。
記事エディターでも問題を追加する時点で同じ確認をし、理由を表示する。

記事そのものは`/blog`で公開されるので、ネタバレを含む記事の公開までは止められない。
この制限は、解禁前の問題ページや記事一覧から解説へたどれる経路を作らないためのものである。

### 表示する場所

- 問題の解説タブ：公式解説の下に、公開日時の昇順で並べる（`GET /problems/{id}/editorials`）。
- 記事ページ：解説している問題へのリンクを本文の前に出す（`GET /posts/{id}`の`problems`）。
- コンテストの解説一覧：終了後に、問題ごとのユーザー解説を並べる（`GET /contests/{id}/editorials`）。

### 問題の作者に通知する

記事を公開したとき、紐付けた問題の作者へ種類`user_editorial`の通知を送る。
同じ記事と問題の組には1回だけ送り、自分の問題には送らない。
記事を削除すると、その記事の通知も消える。

## 代替案

- **問題の作者が記事を選ぶ**：意図しない記事が載ることはないが、作者が動かない限りユーザー解説が増えない。
- **記事の作者が申請し、問題の作者が承認する**：載せる記事を作者が管理できるが、承認画面と通知の往復が要る。まず自由に紐付けられるようにし、困る例が出たら非表示の仕組みを足す。
- **紐付けはいつでも受け付け、表示だけ解禁後にする**：記事を書いた直後に登録できるが、開催中や解禁前に解説記事を公開する流れを後押ししてしまう。
- **紐付けを別のテーブルに置く**：外部キーで整合性を保てるが、下書きと公開版の2組を持つ必要がある。配列の列なら、記事の公開スナップショットと同じ形で扱える。

## 影響

- 問題の作者が、自分の問題に付いたユーザー解説を非表示にする仕組みはまだない。
- アカウント削除で公開済みの記事を残すときは、下書きの問題一覧も公開版に揃える。
- 配布前にマイグレーション`027_user_editorials.sql`を適用する。
- APIをWebより先に配布する。古いAPIは未知のフィールドを拒否するので、新しいWebが送る`problemIds`で記事の保存が失敗する。
