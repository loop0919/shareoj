# ADR 0013: 問題の準備状況をサーバーで判定し、公開とコンテストにも難易度を求める

- 状態：Accepted
- 決定日：2026-09-30
- 一部変更：[ADR 0011](0011-schedule-featured-problems.md)の応募条件（テストケースを追加）

## 背景

作者は、自分の問題を公開、コンテスト、定期便に出せるかどうかを、実際に投稿や登録を試すまで知ることができなかった。
試して失敗しても、理由は分からなかった。
APIの判定は真偽値しか返さず、定期便の不適格はすべて`featured_ineligible`、コンテストの不適格はすべて`contest_conflict`になっていた。
画面は、出せない問題を理由なく選択肢から外すか、固定の1文を出すだけだった。

定期便には、ほかにも2つの問題があった。
応募した後に条件を満たさなくなった問題は、出題時に黙って飛ばされ、作者は気付けなかった。
また、テストケースが0件でも応募でき、出題されても採点できなかった。

## 決定

### 判定をサーバーの1か所にまとめる

保存済みの問題について、提出先（公開、コンテスト、定期便）ごとに、出せない理由をコードで列挙する。
理由は、問題の内容に関するもの（タイトル、問題文、難易度、判定用コード、テストケース、解説）と、問題の状態に関するもの（公開中、公開歴、コンテストへの登録、応募件数の上限）に分かれる。
既存の真偽値の判定は、この理由の一覧が空かどうかで決める。
これにより、画面に示す理由と、実際の投稿や登録の可否が食い違わない。

APIは、作者が自分の問題を取得、保存、公開したときの応答と、作者の一覧の各行に、この判定結果を付ける。
テスターは公開も応募もできないので、判定結果を受け取らない。
判定は保存済みの内容に対して行い、編集中の未保存の変更は含めない。

### 状態を5段階で示す

自分の問題の一覧では、状態を次の5段階だけで示す。

- **×準備中**：コンテストと定期便の内容の条件を満たしていない。押すと足りない項目が開く。
- **✅準備中**：内容の条件を満たしており、コンテストにも定期便にも出せる。
- **応募中（コンテスト）**：開始前のコンテストに登録済み。
- **応募中（定期便）**：定期便に応募中。条件を満たさなくなった場合は、選出されないことと理由を同じように示す。
- **公開中**：公開されている。

✅と×は、コンテストと定期便の内容の条件の和で決める。
コンテストの内容の条件は定期便の条件に含まれるので、✅なら両方に出せる。

### 条件を変える

- 定期便は、コンテストと同じくテストケース1件以上を必須にする。応募時と出題時の両方で確かめる。
- 公開とコンテストの登録にも、作成者が設定する難易度を必須にする（2026-09-30以降）。これまで定期便だけで必須だった。

## 影響

- すでに定期便に応募していて、テストケースのない問題は、出題されなくなる。自分の問題の一覧で、その理由が表示される。
- 難易度を設定せずに公開した問題は、公開されたまま残る。公開内容を更新するときに難易度の設定が必要になる。
- 開始前のコンテストに難易度のない問題が登録されている場合、そのコンテストは難易度を設定するまで保存し直せない。コンテストの終了時の公開は、これまでどおり行われる。
- ジャッジの保守中は公開できる言語がなくなるので、判定用コードを持つ問題はすべて×準備中になる。理由には、保守中の可能性があると添える。
- テストファイルの状態は判定に含めない。保存時に確認済みで、確認済みのファイルは削除されないため。
