# ADR 0016: アカウント削除では公開物を残し、作者を匿名にする

- 状態：Accepted
- 決定日：2026-10-11
- 範囲：設定画面からのアカウント削除、削除済みアカウントの表示と認証

## 背景

利用者が自分でアカウントを削除する手段がなかった。
一方で、利用者が作ったものの多くは、ほかの利用者からも参照されている。
公開した問題には、ほかの利用者の提出・お気に入り・難易度の投票が付く。
終了したコンテストの順位表には、参加者全員の結果が載る。
提出は、問題やコンテストの提出一覧に載る。

`user_profiles`は、問題以外のほぼすべての表から外部キーで参照されている。
作者の表示は、多くのクエリが`user_profiles`を結合してユーザーIDを取り出している。

## 決定

### 公開物は残し、非公開のものは消す

削除するもの：

- プロフィールのユーザーID・アイコン・外部アカウントと、Cognitoのユーザー
- 公開していない問題・記事と、コンテストの下書き
- 公開済みの問題・記事の、公開していない編集内容（下書きを公開版に戻す）
- お気に入り、自分宛ての通知、作成枠
- 残るコンテンツから参照されない画像

残すもの：

- 公開済みの問題・記事、終了したコンテスト
- 提出、コンテストへの参加登録、難易度の投票
- テスターとしての担当（担当した問題の画像の公開範囲もこれに依存する）

開催予定・開催中の自分のコンテストがある間は、削除を受け付けない。
参加登録した利用者や競技中の利用者から、主催者を突然奪わないためである。

### プロフィールの行を残して匿名にする

プロフィールの行は消さず、ユーザーIDを`deleted_`と16進数11桁の値に置き換え、`deleted_at`を記録する。
既存の外部キーと、作者を結合するクエリはそのまま動く。
提出者ごとの順位表の行も、退会した利用者ごとに分かれたまま残る。
画面はこの形のユーザーIDを「退会したユーザー」と表示し、ユーザーページへのリンクを付けない。
この形はユーザーIDとして選べないように予約し、公開のユーザーページは404にする。
元のユーザーIDは解放され、ほかの利用者が使える。

### 削除済みのトークンを拒否する

Cognitoのアクセストークンは、ユーザーを削除しても期限まで有効である。
認証付きのすべてのAPIで、削除済みのアカウントを`401 account_deleted`として拒否する。

### CognitoはAPIの権限で削除する

Googleでログインしたトークンは`openid email`のスコープしか持たず、トークンで呼ぶ`DeleteUser`や`GetUser`を使えない。
APIのLambdaロールに、同じUser Poolに限って`AdminGetUser`と`AdminDeleteUser`を許可する。
Cognitoの削除はDBのトランザクションの中で呼び、失敗したらDBの変更も取り消す。
コミットだけが失敗した場合は、ログインできないままデータが匿名化されずに残る。これは手作業で匿名化する。

## 代替案

- **すべて削除する**：ほかの利用者の順位表・提出一覧・お気に入りから項目が消え、終了したコンテストの記録が変わってしまう。
- **共通の「退会者」1件に付け替える**：参加登録の主キーが衝突し、複数の退会者の結果が順位表の1行にまとまってしまう。
- **Googleのログインに`aws.cognito.signin.user.admin`のスコープを追加して、トークンで削除する**：既存のセッションは再ログインするまで削除できない。また、トークンだけで自分のユーザー属性を書き換えられるようになり、許可する範囲が削除より広がる。

## 影響

- 配布前に`terraform apply`でLambdaロールへ権限を追加し、マイグレーション`026_account_deletion.sql`を適用する。
- 退会した利用者の元のユーザーIDを、別の利用者が取得できる。過去のURL`/users/元のID`は、取得した利用者のページになる。
- 削除の取り消しや猶予期間はない。
