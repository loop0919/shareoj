# ADR 0028: 一覧をページ番号で送り、表示件数を選べるようにし、順位表で自分の行を残す

- 状態：Accepted
- 決定日：2026-10-23
- 範囲：問題一覧、コンテストの順位表、コンテストの提出一覧のページ送りと表示件数、順位表での自分の行の扱い

## 背景

問題一覧（`/problems`）は50件ずつ「前へ／次へ」で送る。
全部で何件・何ページあるかが分からず、離れたページへ直接移れない。
公開された問題が増えて、目当ての問題を探しにくくなった。

コンテストの順位表は、全員の行を1枚の表に出す。
参加者が増えると、自分の順位を探すのにも、表の下にあるFAと正解者数を見るのにも長いスクロールが要る。

コンテストの提出一覧は、問題一覧と同じく50件ずつ「前へ／次へ」で送る。

## 決定

### ページ番号はAtCoderと同じ並びで出す

問題一覧、順位表、提出一覧のページ送りを、ページ番号のボタンの並びにする。
いまのページを p、最後のページを n とすると、次の番号を小さい順に重複なく出す。

- 1 と n
- p から前後に 1, 2, 3, 7, 15, 31, … ページ離れた番号のうち、1 以上 n 以下のもの

離れる幅は 1, 2, 3 のあと、前の幅を2倍して1を足したもの（7, 15, 31, …）である。並べたときの間隔は +1, +1, +1, +4, +8, +16, … になる。
AtCoderのコンテスト一覧で、この並びを2026-10-23に確かめた。

| 全50ページで見ているページ | 出す番号 |
|---|---|
| 1 | 1, 2, 3, 4, 8, 16, 32, 50 |
| 20 | 1, 5, 13, 17, 18, 19, **20**, 21, 22, 23, 27, 35, 50 |
| 50 | 1, 19, 35, 43, 47, 48, 49, 50 |

いまのページの番号は塗りつぶして強調し、押しても何も起きない。
前後のページの番号が必ず並ぶので、「前へ／次へ」と省略記号（…）は置かない。
ページが1つしかないときは、ページ送りを出さない。

ページ送りは表の上と下の両方に置く。
表の上には、ページ送りと並べて件数と表示件数の選択も置く。

### 件数を「全 N 件中 a〜b 件目」で示す

表の上に、全体の件数と、いま表示している範囲を出す。
問題一覧は「全 230 問中 51〜100 問目」、順位表と提出一覧は「全 132 件中 41〜60 件目」のように書く。
順位表は同じ順位の行があり、チーム戦ではチームと個人の行が混ざるので、順位や人数ではなく行の数で数える。

### 表示件数を選べる

表の上の「表示件数」で、1ページの件数を 20、50、100 から選ぶ。
初期値は、問題一覧と提出一覧が50（今と同じ）、順位表が20である。
順位表は、FAと正解者数をスクロールせずに見られることを優先して小さくする。

選んだ件数は、問題一覧、順位表、提出一覧のそれぞれでブラウザーのCookieに保存する。
ほかの表示の設定（ADR 0026のタグの表示など）と同じく、ログインしていなくても使え、すべてのコンテストに共通である。
Cookieに入れるので、問題一覧はサーバーで描画するときから選んだ件数で表示できる。

件数を変えたら、それまで表の先頭にあった行が入るページへ移る。
たとえば20件ずつの3ページ目（41〜60件目）で50件に変えると、41件目を含む1ページ目（1〜50件目）を表示する。

### ページ番号をURLに入れる

いまのページを、URLのクエリ `page` に入れる。
問題一覧は `/problems?page=3`（タグで絞り込んでいれば `tag` と並べる）、コンテストは `?view=standings&page=3` のようにする。
再読み込み、戻る、リンクの共有でも同じページを開ける。
1ページ目では `page` を付けない。
数でない値や1未満の値は1ページ目として扱い、最後のページより大きい値は最後のページとして扱う。

表示件数はURLに入れない。
共有したリンクを開いた人の件数が違えば、同じ `page` でも違う範囲が見える。表示件数は閲覧者の好みであり、リンクに含めない。

問題一覧の canonical は、2ページ目以降ではそのページのURL（`page` を含む）にする。範囲外の `page` を開いたときは、読み替えたページのURLを canonical にする。
ページ番号は、ボタンの見た目をしたリンクにする。検索エンジンが2ページ目以降をたどれる。

コンテストのメニューで表示を切り替えると、今と同じくクエリが外れて1ページ目になる。

ページが1つしかなくても、件数と表示件数の選択は出す。一覧が空のときは、今の空の表示だけを出す。

### 順位表は全件を読み込み、画面でページに分ける

順位表のAPIは今のまま全件を返し、画面でページに分ける。
FAと正解者数は、今と同じく表示中の条件（凍結、オンサイトのみ）のすべての行から数え、どのページでも表の下に出す。

「凍結なしで表示」や「オンサイトのみ表示」を切り替えたら、1ページ目に戻る。
15秒ごとの更新ではページを保つ。更新で行が減って今のページがなくなったら、最後のページを表示する。

### 順位表で自分の行を強調し、ページの外でも出す

ログインしている閲覧者の行を強調する。
個人の行では `handle` が自分のものである行、チームの行では `team.members` に自分が入っている行を自分の行とする。
強調は、行の背景をアクセントの薄い色（`--color-accent-soft`）にし、名前の欄の左端にアクセントの色の太い線を引く。
「あなた」のような見えるラベルは付けない。読み上げでは自分の行と分かるよう、見えない文字で補う。

自分の行が今のページにないときは、同じ行を表の中に1行足して出す。
自分の行が今のページより前（上位）にあれば表の先頭に、後ろ（下位）にあれば表の末尾に置く。末尾は、FAと正解者数の集計行より上である。
足した行と今のページの行の間には、「⋮」だけの区切りの行を挟む。
前か後ろかは順位の数ではなく、全体の並びでの位置で決める。同じ順位の行がページの境目にまたがっても、位置は一つに決まる。

ログインしていないとき、自分の行がない表（参加していない、スタッフである、オンサイトのみ表示で自分がオンサイトでない）では何も足さない。
順位表の集計では1人の行は1つだけなので、足す行は多くても1つである。

自分のハンドルはサーバーで描画するHTMLに含まれない。そのため強調と足した行は、画面が読み込まれてから現れる。そのときの表のずれは受け入れる。

自分のページへ移るボタンは置かない。

### 提出一覧と問題一覧は、APIで件数を指定してページを取る

コンテストの提出一覧（`GET /contests/{id}/submissions` と `GET /my/contests/{id}/submissions`）は、今の `offset` に加えて、1ページの件数 `limit` を受け取る。
応答には、今の `items` と `hasMore` に加えて、条件に合う提出の総数 `total` を入れる。
`limit` を省いたときは今と同じ50件を返す。

問題一覧（`GET /problems`）は、今の `cursor` に加えて `offset` と `limit` を受け取る。
`offset` を指定したときは、公開日時の降順でその件数を飛ばしたところから `limit` 件を返す。
`cursor` を指定したときは、今と同じくそのカーソルの続きから `limit` 件を返す。どちらも指定しないときは先頭から `limit` 件を返す。
`limit` を省いたときは、どの場合も今と同じ50件である。
`cursor` と `offset` を一緒に指定したら `400 invalid_request` にする。
応答は、どの場合も今と同じ `items` と `nextCursor`（返した最後の問題の続きを指すカーソル。最後のページなら空文字）に、絞り込み（作者、タグ）に合う問題の総数 `total` を加えたものにする。
これまでの使い方の応答は、`total` が増えるだけで変わらない。

`limit` は 1 以上 100 以下とし、範囲外は `400 invalid_request` にする。
APIの説明（公開APIのドキュメント）にも `limit`、`offset`、`total` を書く。
`total` を加えるのは問題一覧とコンテストの提出一覧の応答だけで、同じ型を使う問題ごとの提出一覧などには加えない。

提出一覧は、今と同じく15秒ごとの更新で今のページを読み直す。
「オンサイトのみ表示」を切り替えたら1ページ目に戻る。
開催中にチームのメンバーがチームの提出だけを見るときも、同じページ送りを使う。

### 実装時に決めること

- ページ送りと表示件数の部品の名前と分け方、Cookieの名前
- 見た目の細部（ボタンの大きさ、狭い画面での折り返し）。今の表とボタンの見た目に合わせる
- テストの範囲と書き方

## 代替案

- 「前へ／次へ」を残し、件数の表示だけ足す：離れたページへ移れず、問題を探しにくいままである。
- ページ番号を連続して出し、間を「…」で省く（1 … 18 19 20 21 22 … 50）：遠いページへ移るのに何度も押す。利用者が見慣れているAtCoderの並びにそろえる。
- 順位表のAPIもページに分ける：FAと正解者数は全員の行から数えるので、結局すべての行が要る。参加者の数は全件を返しても困らない規模である。
- 表示件数をURLに入れる：共有したリンクで同じ範囲が見えるが、閲覧者が選んだ件数がリンクを開くたびに上書きされる。

## 影響

- 問題一覧、順位表、提出一覧で、何件あるかが分かり、離れたページへ直接移れる。
- 順位表は初期状態で20件ずつになり、FAと正解者数を少ないスクロールで見られる。自分の行は、どのページを見ていても表の中に出る。
- 問題一覧と提出一覧のAPIは、総数を数える問い合わせが1回増える。
- 公開APIに `limit`、`offset`（問題一覧）、`total` が増える。今までの使い方は変わらない。
- 次の一覧は今回は変えない：自分の提出履歴、問題ページの提出の一覧、定期便の順位表、ブログの一覧、プロフィールの一覧。
