# ADR 0015: コンテストを下書きとして保存し、公開時に検証する

- 状態：Accepted
- 決定日：2026-10-11
- 範囲：新しいコンテストの保存と公開。公開済みで開始前のコンテストの編集は変えない

## 背景

これまでコンテストは、最初の保存で`contests`に入り、その時点で公開されていた。
保存にはタイトル、未来の開始日時、終了日時、1問以上の問題と配点がすべて必要で、問題もコンテストの条件を満たしている必要があった。
作成途中の内容は保存できず、画面を閉じると失われた。
保存できた時点でコンテスト一覧に載るので、準備の途中で公開されてしまうこともあった。

`contests`の行は、存在するだけで公開されたものとして扱われている。
公開APIの一覧と詳細、順位表、参加登録、終了時の問題の自動公開、画像の公開範囲が、`contests`の行と開始日時・終了日時を見て判定している。

## 決定

### 下書きを別のテーブルに置く

未公開のコンテストは`contest_drafts`に、内容をJSONのまま保存する。
`contests`と`contest_problems`には、公開したコンテストだけを置く。
公開すると、下書きを検証して同じIDで`contests`と`contest_problems`へ書き込み、同じトランザクションで下書きを削除する。

既存の判定は`contests`の行を見ているので、下書きはどの公開APIからも見えない。
開始日時が過去の下書きを保存しても、問題文や画像が開始済みとして公開されることはない。
画像の参照判定には下書きの説明を加え、作者だけに見せる。

### 保存は緩く、公開は厳しく検証する

下書きは、未入力や範囲外の値を含んでいても保存する。
拒否するのは文字数と問題数の上限、不正な問題ID、極端な数値だけにする。
公開できない理由は[ADR 0013](0013-assess-problem-readiness.md)と同じく、サーバーがコードで列挙して下書きの応答に付ける。
公開時も同じ判定を使い、理由が残っていれば公開しない。

### 開催期間は開始日時とコンテスト時間で入力する

下書きと画面は、開始日時と分単位のコンテスト時間を持つ。
公開時に終了日時へ変換し、`contests`の形と公開APIは変えない。

### 下書きは問題を確保しない

下書きに入れた問題は、ほかのコンテストへの登録や公開を妨げない。
公開時にほかのコンテストに登録済みであれば、`problem_unavailable`として公開できない。

## 代替案

- **`contests`に公開状態の列を足す**：既存の判定すべてに条件を足す必要がある。1か所でも漏れると、開始日時が過去の下書きから問題文が公開される。
- **画面だけで下書きを保持する（localStorage）**：別の端末で続きを編集できず、ブラウザのデータを消すと失われる。
- **下書きでも問題を確保する**：作成途中のまま放置された下書きが、問題の公開や別のコンテストへの登録を止めてしまう。

## 影響

- 新規作成枠は下書きの作成時に消費し、公開では消費しない。
- 公開済みのコンテストを下書きへ戻す操作はない。開始前の編集は、これまでどおり検証してから保存する。
- `PUT /my/contests/{id}`による新規作成は残す。画面は使わない。
- 配布前にマイグレーション`025_contest_drafts.sql`を適用する。
