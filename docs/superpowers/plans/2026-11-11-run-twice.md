# 2ステップ形式（Run-twice） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提出を1ケースにつき2回実行し、作問者の「2ステップ用ジャッジ」が1回目の結果を2回目へ引き継ぐ判定方法「2ステップ形式（Run-twice）」を、ワーカー、API、bridge、Web、CLIに加える。

**Architecture:** ワーカーは既存の対話形式の1ケース実行（`interactive.execute`）に「何回目か」と「引き継ぎ」を渡せるようにし、それを2回呼ぶ`interactive.execute_twice`を足す。下書きとジョブには`checker`、`interactor`と排他の`runTwice`を足し、API、bridge、Web、CLIは対話用ジャッジの扱いをそのまま写す。提出結果の`interactive: true`は「対話履歴を診断として出す」の意味で2ステップ形式でも立て、Webの結果表示を共用する。

**Tech Stack:** Python（`judge/runner`、unittest）、Go（`api/internal/problems`、`api/internal/submissions`、`api/cmd/judge-bridge`、`cli`）、Nuxt 4（Vue 3、zod）、Playwright

**Spec:** [docs/superpowers/specs/2026-11-11-run-twice-design.md](../specs/2026-11-11-run-twice-design.md)（既存の規則は [対話形式](../../judge/interactive-judge.md) と [スペシャルジャッジ](../../judge/special-judge.md)）

## Global Constraints

- 下書きとジョブの項目名は`runTwice`、形は`{"runtime", "source", "protocol"?: "legacy" | "testlib"}`。`checker`、`interactor`、`runTwice`は同時に2つ以上を指定できない。
- 公開APIは`runTwice: true`だけを返し、コードを返さない。提出結果は`interactive: true`を対話形式と2ステップ形式の両方で立てる。
- 現行形式の引数：`test-input expected-output submission-source score <1|2> handoff`（すべて`/box/`の下）。1回目の`handoff`は空で`0o666`、2回目は1回目の内容で`0o444`。
- testlib形式の引数は対話形式と同じ（`test-input test-output expected-output [result -appes]`）。1回目の`test-output`（`tout`）が引き継ぎになり、2回目は`test-input`を引き継ぎの内容に差し替える。
- 引き継ぎの上限は16 MiB（`sandbox.OUTPUT_LIMIT`と同じ16,777,216バイト）。超過と、通常のファイルでないものは提出全体をJE。読むのは1回目がACのときだけ。
- 1回目がAC以外なら2回目を実行しない。点（スコアファイル、testlibの結果ファイル）は2回目だけを使う。
- 計測値：`cpuTimeMs`と`memoryBytes`は2回の大きいほう、`wallTimeMs`は合計。2回目を実行しなければ1回目の値。
- 各回の資源上限、box ID（0と1）、UID/GID、プロセス数は対話形式の値を変えない。採点全体の1,800秒と1,500秒も変えない。
- 診断の見出しは`1回目:`と`2回目:`。2回目を実行しないときは`2回目: 実行しません（1回目の判定: <判定>）`。
- 画面の文言：選択肢「2ステップ形式（Run-twice）」、コード欄の名前「2ステップ用ジャッジ」、問題ページ「2ステップ形式（Run-twice）：プログラムは1ケースにつき2回実行されます。応答を待つ前に出力をflushしてください。」、公開準備「2ステップ用ジャッジのコードが空です」「2ステップ用ジャッジの言語が現在使えません（ジャッジの保守中の可能性があります）」。
- 公開準備の指摘コード：`run_twice_source_missing`、`run_twice_runtime_unavailable`。
- CLI：`problem.toml`の表は`[run_twice]`、コードのファイルは`run_twice.txt`、下書きのキーは`runTwice`。
- ブランチ`feat/run-twice`で作業する。`main`へのpushはAPIを自動で配置するので、Task 9でワーカーの配布が終わるまで`main`へpushしない。
- コマンドはリポジトリのルートで実行する。Pythonは`python3 -m unittest discover -s judge/tests -v`。Goは`nix develop -c go -C api test ./...`と`nix develop -c go -C cli test ./...`（実DBのテストは先に`export TEST_DATABASE_URL='postgresql://openoj:openoj-local@127.0.0.1:15432/openoj?sslmode=disable'`）。Playwrightは`web`で`bun run build`の後に`bun run test <file> --output=<scratchpad>/pw`を`nix develop`の中で実行する。
- コミットメッセージは`prefix: 対応内容`（日本語）。コードを変えたら`graphify update .`を実行する。

## Review Focus

- **ジャッジが引き継ぎを書かずに正常終了する**：空の引き継ぎで2回目を実行し、JEにしない。testlib形式では2回目の`inf`が空になる（Task 1「空の引き継ぎ」）。
- **ジャッジが引き継ぎファイルをリンクやFIFOに置き換える**：ホストのファイルを読まず、待たされもせず、提出全体をJEにする（Task 1「通常のファイルでない引き継ぎ」）。
- **1回目でTLEになるケースが続く部分点の問題**：1ケースを1回のTLEとして数え、2回目の分を二重に数えない。計測値は1回目の値になる（Task 2「1回目のTLEと打ち切り」）。
- **判定方法を対話形式から2ステップ形式へ切り替える**：書いたコードが引き継がれ、`interactor`は`null`になって保存が拒否されない。CLIの`[run_twice]`のpushでも、リモートの`checker`と`interactor`が消える（Task 6「切り替え」、Task 7「置き換え」）。
- **サンプル検証で2回目まで進まないケース**：ケースごとの診断（4 KiB上限）に`1回目:`の履歴と「実行しません」の行が残り、提出者に見える（Task 2「サンプル検証の診断」）。

**Interfaces:**
- Produces:
  - `sandbox.HANDOFF_LIMIT = OUTPUT_LIMIT`
  - `sandbox.prepare_program(box, runtime, artifact, files=None, *, protocol='legacy', interactive=False, result_file=False, run=None, handoff=b'')`。`run`が`1`か`2`で現行形式なら、`/box/handoff`を置いて引数の末尾に`str(run)`と`/box/handoff`を足す。testlib形式で`run == 2`なら、`test-input`に`files['test-input']`でなく`handoff`を書く。`run is None`の動作は変えない。
  - `interactive.execute(job, case, artifact, diagnostic, score_file=False, *, code=None, run=None, handoff=b'')`。`code`は判定コードの辞書で、`None`なら`job['interactor']`。関数内の`job['interactor']`はすべて`code`を使う。`run == 1`で判定がACのとき、返す辞書に`handoff`（`bytes`、読めなければ`None`）を足す。読む場所は現行形式が`boxes[1] / 'handoff'`、testlib形式が`boxes[1] / 'test-output'`で、`sandbox.regular_read(path, sandbox.HANDOFF_LIMIT)`を使い、`OSError`、`ValueError`、上限超過を`None`にする。
  - `interactive.execute_twice(job, case, artifact, diagnostic, score_file=False) -> dict`。`job['runTwice']`を`code`として`execute`を2回呼ぶ。返す辞書は`execute`と同じキー（`verdict`、`cpuTimeMs`、`wallTimeMs`、`memoryBytes`、`score_file`なら2回目の`scoreFile`と`judgeExitCode`）。引き継ぎが`None`なら`dict(verdict='JE', reason='引き継ぎファイルを読めません（16 MiB以下の通常のファイルにしてください）\n')`を返す。
