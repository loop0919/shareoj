# ガイドを読者別に分け直す設計

- 作成日: 2026-11-13
- 状態: 承認待ち
- 対象: サイトのガイド（`web/app/content/docs/*.md`、`web/shared/docs.ts`、`/docs`のページ）

## 目的

ガイドの1ページに、読み手も性格も違う文章が混ざっていて読みづらい。
たとえば「コンテストのルール」には、参加登録の手順、ペナルティの仕様、公開範囲、スタッフ向けの説明が同居している。
文面もAIが書いた癖が強く、例外や条件を漏れなく並べた文が続く。

ガイドを読者ごとに分け、誰向けのページかを画面に明示し、文面を短く書き直す。

## 利用者と決めたこと

- ガイドは想定読者ごとに分ける。
- 読者は「参加者向け」「作問者向け」「開発者向け」のように画面に明示する。
- 大分類（サイドバーと一覧の見出し）を、やることの名前から読者の名前に変える。
- 細かい決まりはガイドから消えてよい。
  必要な人はリポジトリを読めばよい。
- 次の3点は利用者が「その認識で合っている」と認めた、直したい癖である。
  - 例外や条件を漏れなく書こうとして、「〜できますが、〜はできません」「ただし〜」が続く。
  - 1つの節に細かい仕様を全部詰めてあり、読む人が自分に関係する文を探す必要がある。
  - 画面を見れば分かることまで文章で説明している。

これより下は、明記がない限り設計者の判断である。

## 作らないもの

- 入口で読者を選ばせる画面は作らない。
- `docs/`配下の開発者向け文書（ジャッジの運用手順など）は対象外とする。
- ガイドが説明している機能の挙動は変えない。
- スクリーンショットは、書き直しの最後に `bun run docs:screenshots` でまとめて撮り直す（利用者の指定）。
  撮影の内容（どの画面のどこに番号を付けるか）は変えない。

## 失敗とみなす状態

- 1ページの中に、別の読者に向けた節が残っている。
- 削った結果、多くの参加者が当たる決まり（誤答ペナルティの数え方など）まで消えている。
- 利用規約とプライバシーポリシーが参照している内容が、参照先のページから消えている。
- 既存のURLが404になる。

## ページの構成

大分類は3つにする。
「コンテストを開く」は、自作の問題を出す人が読むので作問者向けに入れる。

| 大分類 | slug | タイトル | 扱い |
| --- | --- | --- | --- |
| 参加者向け | `submissions` | 提出と判定結果 | 書き直す |
| 参加者向け | `languages` | 使える言語と実行環境の仕様 | 文面だけ整える |
| 参加者向け | `difficulty` | 難易度の目安 | 文面だけ整える |
| 参加者向け | `contest-participation` | コンテストに参加する | 新設 |
| 参加者向け | `contest-rules` | コンテストのルール | 範囲を狭めて書き直す |
| 参加者向け | `featured` | 定期便 | 範囲を狭めて書き直す |
| 作問者向け | `authoring` | 問題の作成と公開 | 書き直す |
| 作問者向け | `markdown` | Markdown と数式の書き方 | 文面だけ整える |
| 作問者向け | `generator` | 入出力生成と入力検証の使い方 | 文面だけ整える |
| 作問者向け | `checkers` | 判定方法の設定 | 文面だけ整える |
| 作問者向け | `cli` | 作問CLI | 文面だけ整える |
| 作問者向け | `featured-apply` | 定期便に応募する | 新設 |
| 作問者向け | `hosting-contests` | コンテストを開く | 書き直す |
| 開発者向け | `api` | 公開API | 文面だけ整える |

既存のslugは1つも消さないので、転送の追加は要らない。
`/blog/*`からの転送（`legacyDocPaths`）はそのまま残す。

### 分け直すページの中身

**コンテストに参加する（新設）**
読者は、これからコンテストに出る人。
参加登録、チームの作り方と入り方、会場の合言葉、質問の出し方、自分の提出の見方を、手順として書く。
いまの「コンテストのルール」の「参加と開催時間」「質問と回答」と、「問題と提出の公開範囲」のうち参加者の操作にあたる部分が元になる。
画像`contest-join.png`はこのページへ移す。

**コンテストのルール（範囲を狭める）**
読者は、順位の決まり方を確かめたい参加者。
残すのは、公式順位に入る提出、得点と順位、誤答ペナルティ、順位表の凍結、問題と提出がいつ誰に公開されるか、の5つ。
slugとタイトルは変えない。
利用規約（`web/app/pages/terms.vue`）とプライバシーポリシー（`web/app/pages/privacy.vue`）が、このページを「コンテストのルール」という名前で個別規定として参照し、提出の公開時期をこのページに委ねているためである。
コンテストのページの「ルール」リンクもこのページを指したままにする。

**コンテストを開く（書き直す）**
読者は、コンテストを開く作問者。
「コンテストのルール」にあるスタッフ向けの説明（質問に回答できる人と全体公開、スタッフは参加できないこと、スタッフに見える提出）をこちらへ集める。

**定期便（範囲を狭める）**
読者は、定期便を解く人。
出題の日時、新作と復刻、解説と提出の公開時期、順位表の決まり方を残す。
応募の節と、作問者とテスターだけに関係する説明（次回予告でタイトルを表示する操作）は外す。

**定期便に応募する（新設）**
読者は、新作を応募する作問者。
応募の手順、応募できる条件、選ばれ方、取り下げを書く。
画像`featured-apply.png`はこのページへ移す。
応募ページ（`web/app/pages/featured/apply.vue`）の「出題のルール」リンクは、このページを指すように変える。

**提出と判定結果、問題の作成と公開（書き直す）**
読者は変えず、下の文面の決まりに従って手順を中心に組み直す。

## 読者の見せ方

- サイドバーと`/docs`の一覧の見出しを「参加者向け」「作問者向け」「開発者向け」にする。
  `docSections`の`title`を変えれば両方に反映される。
- 各ページの題名の上にある英字の飾り（`SHAREOJ GUIDE`）を、読者のラベルに置き換える。
  リンクや検索から直接来た人にも、誰向けかが題名と一緒に見える。
- パンくずは今も大分類の名前を出しているので、そのまま読者の名前になる。
- `/docs`の導入文「やりたいことごとにまとめています」は、読者ごとにまとめた旨に直す。
- フッターのガイドへのリンク（`footerDocs`）は今の3件のままとする。

## 文面の決まり

書き直すページと、文面だけ整えるページの両方に当てはめる。

- 1ページの読者は1人に決める。
  別の読者に必要な話は、その読者のページへ移してリンクする。
- 手順は番号付きの箇条書きで書く。
  1つの番号には操作を1つだけ入れる。
- 条件、上限、対応表は表か箇条書きにする。
- 1つの節には、その節の題に答える内容だけを書く。
- 「ただし」で始まる例外は、そのページの読者の多くが当たるものだけを残す。
  残すときは、独立した箇条書きの1項目にする。
- 画面のボタン名や項目名を読めば分かる説明は書かない。
- スクリーンショットの番号（①②）は、本文の手順と対応させて残す。
- 敬体（です・ます）で書く。
- 判定結果は`:AC:`、`:WA:`のようにコロンで囲み、色の付いたバッジで表示する（利用者の指定）。
  対象は`AC`、`WA`、`TLE`、`MLE`、`OLE`、`RE`、`CE`、`JE`、`WJ`。
  コードの中と、プログラムが読み書きする文字列そのものを示す箇所は変えない。

### 残すものと削るものの目安

| 残す | 削る |
| --- | --- |
| そのページの読者のほとんどが当たる決まり | ごく一部の人だけが当たる例外 |
| 順位や得点に直接かかわる決まり | 内部の処理の順序や実装の都合 |
| 利用規約とプライバシーポリシーが参照する内容 | 入力欄を見れば分かる文字種や桁数 |
| 上限のうち、作業の計画に影響するもの（作成枠、提出の回数制限） | 更新の間隔など、知らなくても困らない数値 |

削ってよいものの例を挙げる。

- 「一度スタッフになった人は、外れたあともそのコンテストに参加できません」
- 「会場の合言葉は英数字とアンダースコア（_）で、大文字と小文字を区別します」
- 「一覧は15秒ごとに更新し、『質問を更新』でも最新の内容を取得できます」
- 「提出結果では1 MB＝1,000,000バイト、問題ページのメモリ制限では1 MiB＝1,048,576バイトで表示します」

文面だけ整えるページ（`languages`、`markdown`、`generator`、`checkers`、`cli`、`api`、`difficulty`）は参照用の性格が強い。
表、コード例、数値は削らず、地の文の言い回しだけを上の決まりに合わせる。

### 書き直しの見本

「コンテストに参加する」の最初の節を例に示す。

いまの文面：

> ログイン後、開始前または開催中に「参加する」を押すと参加登録できます。
> 登録した時点で、未提出でも0点で順位表に表示されます。
> 開催中の提出には参加登録が必要です。
> 終了後は参加登録できませんが、練習として提出できます。
>
> チーム戦では、②「個人参加」で1人で参加するか、③「チーム参加」で移るチームのページで、チームを作るか、メンバーから聞いた参加コードでチームに入ります。
> 個人参加した人も、開始前ならチームのページでチームに切り替えられます。
> 開始後は、個人参加からチームに切り替えることも、チームを抜けることも、メンバーを外すこともできません。

書き直した文面：

```markdown
## 参加登録する {#join}

1. ログインして、コンテストのページを開きます。
2. 「参加する」を押します。

- 登録は終了時刻まで受け付けます。
- 登録すると、提出していなくても0点で順位表に載ります。
- 終了後は登録できませんが、練習として提出できます。

## チームで参加する {#team}

![チーム戦のコンテストの参加欄。①会場の合言葉、②個人参加、③チーム参加](/images/docs/contest-join.png)

チーム戦のコンテストでは、参加のしかたを選びます。

| 参加のしかた | 操作 |
| --- | --- |
| 1人で参加する | ②「個人参加」を押す |
| チームを作る | ③「チーム参加」を押し、チームを作って参加コードをメンバーに伝える |
| チームに入る | ③「チーム参加」を押し、メンバーから聞いた参加コードを入れる |

チームの変更は開始前に済ませてください。
開始後は、チームに入ることも抜けることもできません。
```

## リンクとテストの直し

- ガイド同士のリンクと、アプリ内からガイドへのリンクを、移した節の新しい場所に合わせる。
  対象は`/docs/contest-rules#clarifications`、`/docs/contest-rules#visibility`、`/docs/featured#apply`、`/docs/featured`を指しているリンクである。
- 節を移すと`{#id}`の位置が変わる。
  `web/tests/guides.spec.ts`は本文中のリンク先の節があることを確かめているので、このテストが通る状態を保つ。
- `web/tests/guides.spec.ts`には、ガイドの本文や見出しをそのまま期待値にしたテストがある（定期便の出題時刻の一文、「コンテストのルール」の目次の「参加と開催時間」など）。
  新しい文面に合わせて期待値を直す。
  JSTの明記のように、テストが守っている事実は新しい文面にも残す。
- `web/tests/seo.spec.ts`のガイドの一覧に、新設の2ページを加える。
- `web/README.md`のガイドの説明を、新しい構成に合わせる。

## 進め方

2段階に分ける。
1段階目の文面を利用者が読んで文体を確かめてから、2段階目へ進む。

1. 大分類の変更、読者のラベル、コンテストの3ページ（`contest-participation`、`contest-rules`、`hosting-contests`）。
2. 残りのページ（定期便の2ページ、`submissions`、`authoring`、文面だけ整える7ページ）。

作業はブランチ`feat/guides-by-reader`で行う。
1段階目だけの状態は、未分割の「定期便」が参加者向けの下に残るなど中途半端なので、mainには入れない。
利用者は1段階目をブランチの上で読み、2段階目が終わってからまとめてmainに入れる。

本番への配布はこの設計に含めない。

## 未マージのWebhookブランチとの関係

`feat/contest-webhooks`（未マージ）は、ガイドに`webhooks`のページを加え、`hosting-contests.md`と`contest-rules.md`、`web/shared/docs.ts`、ガイドのテストを変更している。

- この作業はいまのmainを土台にする。
- 後からmainに入る側が衝突を解く。
- `webhooks`のページは「作問者向け」の「コンテストを開く」の次に置き、文面だけ整える。
- Webhookブランチが`contest-rules.md`の凍結の節に足した作成者向けの一文は、`hosting-contests.md`へ移す。

## 移した節への外部リンク

`/docs/contest-rules#participation`や`/docs/featured#apply`のように、別のページへ移る節を指す外部のリンクは、元のページの先頭に着く。
元のページに案内だけの節は残さない。
代わりに、「コンテストのルール」の冒頭に「コンテストに参加する」へのリンクを、「定期便」の冒頭か末尾に「定期便に応募する」へのリンクを1行置く。

## 事実と合わない記述

書き直すページは、記述をいまの実装と突き合わせ、合わないものは実装に合わせて直す。
少なくとも「定期便」の順位の説明は、点数で順位を決める今の実装（ADR 0033、`web/app/pages/featured/standings.vue`）より前の内容のままである。
文面だけ整えるページでは、気づいた誤りだけを直す。

## 確かめ方

- `web/tests/guides.spec.ts`と`web/tests/seo.spec.ts`が通る。
- 各ページを開き、読者のラベルが題名の上に出ること、サイドバーの見出しが読者の名前になっていることを見る。
- 書き直した各ページを、想定読者になったつもりで頭から読み、別の読者向けの節が残っていないかを確かめる。
- 利用規約とプライバシーポリシーから「コンテストのルール」へ飛び、提出の公開時期が書かれていることを確かめる。

## 作り手に任せること

- 各ページの節の順番と見出しの文言。
- 「残すものと削るものの目安」に照らした、個々の文の残す・削るの判断。
- 読者のラベルの見た目（色、大きさ）。
  いまの英字の飾りと同じ位置と大きさを基本とする。
- 新設ページの`description`と`lead`の文言。
