# マイページのフォルダ分けの設計

- 作成日: 2026-11-26
- 状態: 実装済み（決定は[ADR 0044](../../adr/0044-sort-own-content-into-folders.md)）
- 対象: API（`api/`）、データベース、Web（`web/`）。ジャッジとCLIは変えない。

## 目的

問題が増えると、マイページの一覧から目当てのものを探しにくい。
今の一覧は「自分の問題」「テスト中の問題」「記事」のタブごとに1本で、絞り込みは状態だけである。

利用者は、出す先ごとに分けて持ちたい。
挙げた例は次のとおり。

- コンテストAに出す用
- 定期便用
- Aさんから預かった、出す先がまだ決まっていない問題用

自分で作ったフォルダに問題と記事を入れ、フォルダを開けば、その出す先に関わるものが1か所で見えるようにする。

## 利用者と決めたこと

- フォルダは利用者が自分で作り、名前を付ける。
  コンテストや依頼者から自動では作らない。
- 1つの問題や記事は、1つのフォルダに入る。
  複数のラベルを付ける形にはしない。
- フォルダは入れ子にできる（「コンテスト用」の中に「コンテストAに出す用」）。
  深さは3段までとする。
- 1つのフォルダに、自分の問題、テスト中の問題、記事が一緒に並ぶ。
  利用者は2つの画面イメージを見比べ、この形（A案）を選んだ。
- 「自分の問題」「テスト中の問題」「記事」の3つのタブは、「問題と記事」1つにまとまる。
  「コンテスト」「通知」のタブは今のまま残す。
- 左にフォルダの一覧、右に開いたフォルダの中身を出す。
  種類と状態は、中身の上のプルダウンで絞り込む。
- どのフォルダにも入れていないものは「未整理」に出る。
  「すべて」を選ぶと全件が出る。
- 行をドラッグして、左のフォルダに落とすと入る。
  「未整理」に落とすとフォルダから出る。
- 行のチェックボックスで複数選び、まとめてドラッグできる。
- スマホとキーボード操作では、行の操作から「フォルダへ移動」を選んで入れる。
- フォルダもドラッグで別のフォルダの中に入れられる。
- フォルダを開いた状態で「新規問題」「新規記事」を押すと、できたものはそのフォルダに入る。
  「すべて」や「未整理」から作ったものと、テスター招待で増えた問題は「未整理」に入る。
- フォルダを消すと、中身は「未整理」に戻る。
  問題や記事は消えない。
- フォルダの名前はあとから変えられる。
- この画面はベータ版として出し、利用者が自分で切り替える。
  3つのタブがまとまる変化が大きいので、合わなければ今の画面に戻せるようにするためである。
  - スイッチはマイページのタブの上に置く。
  - 初期状態はオフで、オフの間は今の3つのタブがそのまま出る。
  - 設定はアカウントに保存する。
  - オフに戻しても、フォルダと振り分けは残る。
  - スイッチのそばに、GitHubの機能要望Issueへのリンクを置く。
- 対象はマイページだけである。

これより下は、明記がない限り設計者の判断である。

## 作らないもの

- コンテストへの問題登録や定期便の応募など、問題を選ぶほかの画面には、フォルダを出さない。
- フォルダは本人だけのものである。
  公開ページ、共同作成者、テスター、問題の作者には見えず、共有もできない。
- フォルダをコンテストや依頼者と結び付けない。
  フォルダ名とコンテスト名が同じでも、ただの名前である。
- 「コンテスト」タブのコンテストは、フォルダに入れない。
- フォルダの並びを手で入れ替える機能は作らない。
  同じ階層のフォルダは名前の順に並ぶ。
- フォルダによって公開範囲や権限は変わらない。
- ベータを外して既定の画面にする作業は、今回は含めない。
  使われ方を見てから別に決める。
- CLIからのフォルダ操作は作らない。

## 失敗とみなす状態

- ベータをオフにしている利用者のマイページが、今と少しでも違う。
- フォルダを消したとき、またはベータをオフにしたときに、問題や記事が消える、あるいは一覧に出なくなる。
- フォルダの操作で、問題や記事の内容、公開状態、更新日時が変わる。
- 他人のフォルダが読める、または書ける。
- 自分が開けない問題や記事のIDを送って、それが存在するかどうかを応答の違いから知ることができる。
- 件数の多い利用者で、フォルダの件数や絞り込みが、読み込んだ分だけで数えられ、実際より少なく出る。
- スマホやキーボードだけでは、フォルダに入れられない。
- ドラッグの途中で通信に失敗したのに、画面では入ったように見える。

## データ

移行ファイル`048_content_folders.sql`で足す。

### フォルダ

`content_folders`

| 列 | 内容 |
| --- | --- |
| `id` | UUID。主キー。 |
| `owner_id` | 持ち主。`user_profiles(owner_id)`を参照する。 |
| `parent_id` | 親フォルダ。最上位は`NULL`。親が消えると一緒に消える。 |
| `name` | 名前。前後の空白を除いて1〜40文字。 |
| `created_at` | 作成日時。 |

- 同じ親の下に、同じ名前のフォルダは作れない。
  最上位どうしも同じである。
- 1人が持てるフォルダは100個までとする。
- 深さは3段までとする。
  移動のときは、動かすフォルダの下の段も含めて数える。
- 親は自分のフォルダに限る。
  自分自身や自分の下のフォルダを親にする移動は拒否する。

### 振り分け

問題と記事で表を分ける。
本体が消えたときに、参照の制約で振り分けも消えるようにするためである。

`problem_folder_items`

| 列 | 内容 |
| --- | --- |
| `owner_id` | 振り分けた人。 |
| `problem_id` | `problem_drafts(id)`を参照し、問題が消えると一緒に消える。 |
| `folder_id` | `content_folders(id)`を参照し、フォルダが消えると一緒に消える。 |

主キーは`(owner_id, problem_id)`である。
`post_folder_items`も同じ形で、`blog_posts(id)`を参照する。

- 行がないものが「未整理」である。
- 自分の問題とテスト中の問題は、どちらも`problem_drafts`の行なので、同じ表で扱う。
  同じ問題を作者とテスターが別々のフォルダに入れても、互いに影響しない。
- テスターから外れた問題の行は残す。
  もう一度テスターになれば元のフォルダに出る。
  外れている間は、APIがその行を返さない（「API」の節）。

### ベータの切り替え

`user_profiles`に、フォルダ表示を使うかどうかの真偽値の列を足す。
既定は偽である。
公開プロフィールの応答には含めない。

### アカウントの削除

アカウントを削除するとき、その人の`content_folders`を消す。
振り分けは一緒に消える。
`api/internal/accounts/store.go`の`cleanup`に足す。

## API

すべて`/my`の下で、ログインが要る。
応答はほかの`/my`と同じく保存させない。

| メソッドとパス | 内容 |
| --- | --- |
| `GET /my/folders` | 自分のフォルダすべてと、いま開ける問題と記事の振り分けを返す。 |
| `POST /my/folders` | フォルダを作る。名前と親を受け取る。 |
| `PUT /my/folders/{id}` | 名前と親を変える。 |
| `DELETE /my/folders/{id}` | フォルダと、その下のフォルダを消す。 |
| `PUT /my/folder-items` | 問題と記事をまとめて1つのフォルダに入れる。フォルダを指定しなければ未整理に戻す。 |
| `PUT /my/folder-view` | ベータの切り替えを保存する。 |

ベータの切り替えは、プロフィールの保存とは別の呼び出しにする。
プロフィールの保存は版の番号で衝突を調べるので、同じ呼び出しにすると、スイッチを押しただけで、開いたままの設定画面の保存が失敗する。

### 振り分けを返す範囲

`GET /my/folders`が返す振り分けは、次のものに限る。

- 問題: 自分が作者か、`can_manage_problem`が真である。
- 記事: 自分が作者である。

テスターから外れた問題の行をそのまま返すと、作者がその問題を消したかどうかが、行の有無から分かってしまう。

### 一覧は今の3つを使う

問題と記事の一覧（`GET /my/problems`、`GET /my/problems?role=tester`、`GET /my/posts`）は、次の1点を除いて変えない。
画面が3つの一覧と`GET /my/folders`を読み、IDで突き合わせる。

- テスト中の問題の一覧に、作者のハンドルを足す。
  今は、コンテストの作成者として見えている問題にしか作者が入っていない。
  項目が増えるだけで、オフの画面はこの値を使わない。
  テスターは問題を開けば作者が分かるので、見える範囲は広がらない。
- それ以外は一覧のSQLに手を入れず、ベータをオフにした利用者の経路を変えない。
- フォルダの件数と絞り込みには全件が要る。
  フォルダ表示では、3つの一覧を最後のページまで読む。
  今も状態で絞り込むと最後まで読むので、同じ扱いである。

### 振り分けの検査

`PUT /my/folder-items`は、送られたIDのうち、次に当てはまるものだけを入れる。

- 問題: 自分が作者か、`can_manage_problem`が真である。
- 記事: 自分が作者である。

当てはまらないIDと、存在しないIDは、同じ応答で区別なく無視する。
1回に送れるのは100件までとする。
送り先のフォルダが自分のものでなければ404を返す。

### 上限を超えたとき

- フォルダが100個ある、深さが3段を超える、同じ名前がある、のいずれでも、理由が分かるコードで拒否する。
- 画面は、理由を日本語で示し、何も変わっていないことを伝える。

## 画面

### 切り替えスイッチ

- マイページのタブの上に「フォルダ表示（ベータ）」のスイッチを置く。
- そばに一文の説明と、機能要望Issueへのリンクを置く。
- 押すとすぐ保存し、その場で表示が切り替わる。
  保存に失敗したら、スイッチを元に戻して伝える。
- オフのとき、タブと一覧は今とまったく同じである。

### タブとURL

- オンのとき、タブは「問題と記事」「コンテスト」「通知」の3つになる。
- URLは`/my?tab=library`とし、開いているフォルダ、種類、状態もクエリに持つ。
  再読み込みや戻る操作で同じ表示に戻る。
- オンのときに今のURL（`tab=problems`、`tab=testing`、`tab=posts`）で来たら、「問題と記事」を、その種類で絞り込んだ状態で開く。
  ログイン後の戻り先や通知からのリンクを変えずに済む。
- オフのときに`tab=library`で来たら、「自分の問題」を開く。

### フォルダの一覧

- 上から「すべて」、利用者のフォルダ、「未整理」の順に並べる。
- フォルダは入れ子で字下げし、開閉できる。
  開いているフォルダの親は開いた状態にする。
- それぞれに件数を出す。
  フォルダの件数は、下の段のフォルダの分を含める。
- 一番下に「フォルダを作る」を置く。
  開いているフォルダがあれば、その中に作る。
- フォルダの行から、名前の変更、移動、削除ができる。
- 削除の確認には、消えるフォルダの数と、未整理に戻る件数を出す。
- フォルダが1つもないときは、作り方と入れ方を一文で案内する。

### 中身の一覧

- 開いたフォルダに直接入っているものを出す。
  下の段のフォルダは、一覧の先頭にフォルダの行として出し、押すとそのフォルダに入る。
- 一覧の上に、今いる場所を「コンテスト用 / 第3回コンテスト」のように出す。
  途中の名前を押すと、そのフォルダに移る。
- 列は、選択、種類、タイトル、状態、更新日時、難易度、操作とする。
  記事の難易度は空にする。
- 種類は「自分の問題」「テスト中」「記事」の3つである。
- テスト中の問題には、作者のハンドルを添える。
  利用者が分けたい軸に「誰からの依頼か」があり、見た画面イメージにも作者が出ていた。
  コンテストの作成者として見えている問題には、今と同じくコンテスト名も添える。
- 並びは更新日時の新しい順で、種類をまたいで混ぜる。
- 操作は今の一覧と同じものを出す（編集、閲覧、予約の変更、定期便応募の取り下げ）。
- 「新規問題」「新規記事」のボタンを一覧の上に置く。

### 絞り込み

- 種類: すべて、自分の問題、テスト中、記事。
- 状態: 準備中、応募中、公開予約中、公開中。
  記事の「下書き」は準備中、「公開中」は公開中として数える。
- 2つは組み合わせられる。
  件数は開いているフォルダの中で、もう一方の絞り込みも掛けて数える。

### 並び順

- 「更新が新しい順」（初め）、「作成が新しい順」、「公開が新しい順」から選ぶ。
- 「公開が新しい順」は、公開済み、公開予約中、それ以外の順に並べる。
  公開済みは公開が新しい順、公開予約中は公開が近い順、それ以外は更新が新しい順である。
- 行の2行目の日時は、並べた日時を出す（「更新」「作成」「公開」）。
  公開順で、まだ公開していない行は更新日時を出す。
- 選んだ並び順はブラウザに覚え、URLには入れない。
  絞り込みは今いる場所の一部だが、並び順は見る人の習慣だからである。
- 一覧のAPIに、問題の`createdAt`と`publishedAt`、記事の`createdAt`を足した。
  記事には作成日時の列がなかったので、移行049で足した。
  それまでにある記事は、更新日時と公開日時の早いほうを作成日時とする。

### ドラッグ

- 行をつかむと、落とせるフォルダが分かるように色を変える。
- 選択した行のどれかをつかむと、選択した全部が動く。
  つかんでいる間、件数を出す。
- 落としたら、先に画面を動かし、保存に失敗したら元に戻して伝える。
  101件以上を落として途中で失敗したときは、移動できた分を残す（「実装で決めたこと」）。
- 行はすでに入っているフォルダには落とせない。
- フォルダをフォルダに落とすと、中に入る。
  深さの上限を超える落とし先と、今の親には落とせないようにする。
- ドラッグ用のライブラリは足さず、ブラウザの機能で作る。

### ドラッグを使わない操作

- 行の「⋯」のメニューに「フォルダへ移動」を置く。
  押すとフォルダを選ぶダイアログが開く。
- 複数選んでいるときは、一覧の上に「選んだN件をフォルダへ移動」を出す。
- フォルダの移動も、フォルダの行の操作からできる。
- どれもキーボードだけで終えられる。

### スマホ

- 幅が狭いときは、フォルダの一覧を左に置かない。
  一覧の上に今のフォルダ名を出し、押すとフォルダの一覧が開く。
- 中身は、広い画面と同じ2行の行で出す。
  行の操作のボタンは、行の下に回る。
- ドラッグは使わず、「フォルダへ移動」で入れる。

### 新しく作ったものをフォルダに入れる

- フォルダを開いた状態で「新規問題」「新規記事」を押すと、作成画面にフォルダのIDを渡す。
- 作成画面は、最初の保存が成功したあとに、そのフォルダへ振り分ける。
- 振り分けに失敗しても、5秒で終わらなくても、保存は成功として扱う。
  そのときは「未整理」に出る。

## テスト

- API
  - 他人のフォルダの取得、変更、削除、振り分け先への指定が、どれも通らない。
  - 開けない問題のID、他人の記事のID、存在しないIDを振り分けに送ると、同じ応答になり、行が増えない。
  - テスターが、テスト中の問題を自分のフォルダに入れられる。作者の振り分けは変わらない。
  - テスターから外れると、その問題の振り分けが`GET /my/folders`に出ない。もう一度テスターになると、元のフォルダで出る。
  - テスト中の問題の一覧に、招待で入った問題の作者が入る。
  - 深さ、個数、同じ名前、自分の下への移動が、それぞれ拒否される。
  - フォルダを消すと、下のフォルダと振り分けが消え、問題と記事は残る。
  - 問題や記事を消すと、振り分けが消える。
  - アカウントを削除すると、フォルダと振り分けが消える。
  - 公開プロフィールに切り替えの値が出ない。
- Web
  - オフのとき、タブと一覧が今と同じである。
  - オンにすると3種類が1つの一覧に並び、フォルダと絞り込みで件数が合う。
  - テスト中の行に作者が出る。
  - ドラッグで入れられ、再読み込みしても入っている。
  - 複数選んでまとめて入れられる。
  - 保存に失敗すると、行が元のフォルダに戻る。
  - キーボードだけで「フォルダへ移動」を終えられる。
  - スマホ幅で、フォルダの切り替えと「フォルダへ移動」が使える。
  - フォルダを開いて「新規問題」から作ると、そのフォルダに出る。
  - オンのときに`tab=testing`で開くと、テスト中で絞り込まれている。
  - 51件以上あるとき、件数が全件で数えられる。

## 文書

- ADRを1本足す。
  1つのものは1つのフォルダに入れること、3種類をまたぐこと、ベータとして切り替えることと、その理由を書く。
- 作問者向けのサイト内ガイドに、フォルダ表示の短い節を足す。
  ベータであることと、オフに戻せることを書く。
- `web/README.md`のマイページの説明を直す。

## 配布

mainへのpushで動く配布（`.github/workflows/deploy-dev.yml`）は、APIを出してから移行を流し、最後にWebを出す。
40b49bbb（`feat: フォルダ表示の切り替えをアカウントに保存し、アカウントの削除でフォルダも消す`）以降のAPIは、ログインが要る呼び出しのたびに`user_profiles.folder_view`を読む。
そのため、このブランチを一度にpushすると、移行が終わるまで、ログインが要る呼び出しの多くが503を返す。
並び順のために足した移行049（記事の作成日時の列）も同じで、並び順を足したコミットから`GET /my/posts`がこの列を読む。
そこで、移行のコミットを2つとも先頭に並べてある。
次の順に2回に分けてpushする。
コミットの番号は作り直すと変わるので、件名でも確かめる。

1. `git push origin 5478a5a1:main`で、mainを5478a5a1（`feat: 記事に作成日時の列を足す（移行049）`）までpushする。
   この時点で移行048と049はでき上がっていて、新しい列を読むコードはまだない。
2. その配布が終わるのを待ち、移行の手順（`Apply database migrations`）が成功したことを確かめる。
3. 残りをpushする。
   配布はAPIのあとにWebを出すので、Webが先に出てスイッチを保存できなくなることはない。

既定がオフなので、配布しただけでは誰の画面も変わらない。

## 実装者に任せること

- 表、列、エンドポイント、コンポーネントの名前。
- 深さ、個数、同じ名前の制約を、データベースとAPIのどちらで守るか。
  同時に2つの操作が来ても上限を超えないことは必須である。
- ベータの切り替えを保存する呼び出しの形。
- フォルダを選ぶダイアログの見た目。
  既存のダイアログに合わせる。
- 3つの一覧を最後まで読む間の表示。
- スイッチのそばに置く説明の文言と、空のときの案内の文言。

## 実装で決めたこと

上の各節のうち、次と食い違っていたところは実装に合わせて直してある。

- 101件以上をまとめて移動し、2回目以降の100件で失敗したときは、移動できた分を残す。
  画面には「{N}件中{M}件を移動しました。残りは移動できませんでした。もう一度お試しください。」と出す。
  最初の100件で失敗したら、全部を元に戻す。
- フォルダの作成と名前の変更は、保存に失敗してもダイアログを開いたままにし、ダイアログの中にエラーを出して入力を残す。
- フォルダの作成はAPIの応答を待ってから一覧に出す。
  ほかの操作は先に画面を動かす。
- 保存は呼ばれた順に1件ずつ行う。
  続けて2回落としたとき、先の失敗があとの結果を打ち消さないようにするためである。
- 行はすでに入っているフォルダには落とせない。
  フォルダは今の親には落とせない。
- スマホのフォルダ切り替えのボタンは「フォルダ: {名前}」と表示する。
  見えている文字をそのまま読み上げの名前にするためである。
- フォルダの中から作った問題と記事の振り分けは、5秒で打ち切る。
  打ち切ったときは「未整理」に出る。
- フォルダが1つもないときの案内は「「フォルダを作る」でフォルダを作り、行をドラッグするか、行の「⋯」から「フォルダへ移動」を選ぶと、問題や記事を入れられます。」とする。
- 絞り込みの件数はもう一方の絞り込みも掛けた数である。
- 開いているフォルダと絞り込みは、画面が自分でも持ち、押したらすぐに表示を変える。
  URLは、マイページの遷移の確認が済んでから追いつく。
  URLだけを元にすると、続けて変えたときに、追いつく前の値から次の変更を作って先の変更を消していた。
- 種類と状態の絞り込みは、ボタンの列をやめて「種類」「状態」の2つのプルダウンにした。
  ボタンの列を2段に並べると、一覧の上が絞り込みで埋まるためである。
  選択肢には「記事（1）」のように件数を出し、絞り込んでいる間はプルダウンに色を付ける。
- 一覧の「種類」の列は、種類ごとに形と色の違うアイコンで出す。
  3種類が1つの一覧に並ぶと、文字だけでは見分けにくいためである。
  名前は、ポインタを載せたときにアイコンの横へ出す。
  ホバーのない画面とスマホでは、名前を行の2行目の先頭に出す。
- 一覧は列を並べた表にせず、1件を2行で出す。
  1行目にアイコンと題名、2行目に状態、更新日時、難易度を並べ、入りきらなければ折り返す。
  左にフォルダの一覧があるので、一覧の幅は最大でも784pxしかなく、7列の表は横スクロールなしでは入らなかったためである。
  一覧の幅が36remより狭いときは、操作のボタンを行の下に回す。
  公開予約の日時は、状態と同じ枠の中に分までで出す。
  更新日時と並んだときに、2つの日時が続いて読みにくかったためである。
  分までで出すのは、ベータをオフにした一覧も同じである（秒と「(JST)」を外した）。
- 行の操作は「編集」「閲覧」「⋯」の3つにする。
  「フォルダへ移動」「予約を変更」「定期便の応募を取り下げる」は「⋯」のメニューに入れる。
  ベータをオフにした一覧では、「予約を変更」と取り下げは今までどおり行のボタンである。
- Webサーバーはフォルダの4つのエラーコード（`folder_limit`、`folder_depth`、`folder_name_taken`、`folder_cycle`）を画面に渡す。
- 外部キーの列（`content_folders.parent_id`、`problem_folder_items.problem_id`、`post_folder_items.post_id`）に索引を張った。
- 定期便の取り下げの確認ダイアログは、開いている間だけ作る。
  行の部品を分けた結果で、表示と操作は変わらない。
- ベータの切り替えは`PUT /my/folder-view`で保存する。

## まだ確かめていないこと

- 実機のスマホでの操作。
- Safariで、キーボードでフォーカスしたボタンからフォルダの操作のメニューを開き、項目をマウスで押したときに、その項目の操作が行われるか。
  メニューは`focusout`で閉じる。
  Safariはマウスで押したボタンにフォーカスを移さないので、押したときにメニューが先に閉じ、操作が行われないおそれがある。
