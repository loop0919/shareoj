# 運用費のページの運用

AWSの請求額を月に一度読み、GitHub Pagesの「ShareOJの運用費」に、月ごとの収入・支出・残高の表として載せる仕組みの手引きである。
読む人は、このリポジトリの管理者である。
設計は[運用費ページの設計](superpowers/specs/2026-11-26-running-cost-page-design.md)にある。

## 何がどこにあるか

| もの | 場所 |
| --- | --- |
| ワークフロー | `.github/workflows/cost-report.yml` |
| 取得とページのスクリプト | `cost-report/` |
| 支出の列と割り振り、注記、リンク | `cost-report/config.json` |
| 月ごとの支出 | `cost-data`ブランチの`costs.json`（ワークフローが書く） |
| 月ごとの収入 | `cost-data`ブランチの`income.json`（手で書く） |
| AWSのロール | `infra/deploy-access/`（[説明](../infra/README.md#運用費を読むロール)） |

`main`には金額のデータを置かない。
`main`へのpushは`Deploy dev`を走らせるためである。

## いつ動くか

- 毎月8日から14日の09:23（日本時間）に動く。
- AWSが前月の額を確定していれば、その日に載る。
  確定していなければ何も変えずに終わり、翌日にまた試す。
- 14日になっても確定していなければ、その実行は失敗し、GitHubの通知が届く。
- 一度載せたあとの実行は、金額が同じなら同じページを出し直すだけである。
  `costs.json`は書き換えない。
- AWSの記録があとから直されたときは、次の実行で過去の月も直る。
  直るのは、実行日から12か月前までの月である。それより古い月は保存した値のまま残る。

## 手で動かす

```console
gh workflow run cost-report.yml
gh workflow run cost-report.yml -f fetch=false
```

- 1つめは、AWSから読み直して載せる。
  前月がまだ確定していないと失敗する。
- 2つめは、AWSを読まずに、保存済みの金額でページだけ作り直す。
  収入、ページの見た目、列の名前と組み合わせ、注記、リンクを変えたあとに使う。
  サービスの割り振り（`services`と`record_types`）を変えたときは、1つめを使う。
  保存済みの金額は区分ごとの額なので、AWSから読み直さないと割り振りは変わらない。

## 収入を書く

GitHub Sponsorsで支援を受けた月に、`cost-data`ブランチの`income.json`へ1行足す。
GitHubの画面でそのまま編集できる。`main`には触れないので、`Deploy dev`は走らない。

```json
{
  "2026-12": "25.00",
  "2027-01": "30.00"
}
```

- 月は`2026-12`の形、額は米ドルで、その月に支援者が払った額の合計を書く。
  額はSponsorsのダッシュボードで確かめる。
- 支援者の名前や人数は書かない。
- 書いた収入は、その月の支出が確定して行ができたときに、一緒に載る。
  12月の収入は、12月分の請求が確定する1月8日ごろに載る。
- すでに行がある月の収入を足したり直したりしたときは、`fetch=false`で手で動かす。
  動かさなくても、次の定期実行で載る。
- 月の形や額がおかしいと、実行は失敗し、ページは変わらない。
  ログに、どの月かが出る。

## 支出の列を直す

支出は、区分（`groups`）に分けて保存し、ページでは列（`columns`）にまとめて出す。

| 設定 | 役目 |
| --- | --- |
| `groups` | AWSのサービスを区分に割り振る。区分の`id`ごとの額が`costs.json`に保存される |
| `columns` | 区分を、ページの支出の列にまとめる。上から順に、左から並ぶ |

- `services`にAWSのサービス名を書くと、そのサービスの料金がその区分に入る。
- `record_types`に料金の種類を書いた区分は、サービスより先に当てはめる。
  前払いと消費税がこれに当たる。
- どの区分にも当たらないサービスは`other`に入る。
- 区分は、どれか1つの列の`groups`に書く。
  どの列にも書いていない区分の額は、`other`を書いた列に入る。
- 列の名前や組み合わせを変えるだけなら、`fetch=false`で作り直せば全部の月が直る。
- サービスの割り振りを変えて読み直すと、実行日から12か月前までの月が新しい割り振りに直る。
  それより古い月は、元の割り振りのまま残る。

サービス名を確かめるときは、手元でCost Explorerを読む。
生の応答にはサービスごとの金額が入っている。
置いてよいのは`.local/cost-report/`だけで、リポジトリ、`cost-data`ブランチ、Actionsのログや成果物には残さない。

## 注記を書く

| 設定 | 出る場所 |
| --- | --- |
| `standing_note` | 表の下の注記の先頭に、常に出る。`null`で消える |
| `month_notes`の`"2026-10"`など | 表の下に「※1」のように番号付きで出て、その月の行に同じ番号が付く |

- 番号は、古い月から順に付く。月が増えても、付いた番号は変わらない。
- `month_notes`の文の中の`{prepay}`は、その月の前払いの額に置き換わる。

## 予約購入をしたとき

RDSなどを予約購入（リザーブドインスタンス）で前払いすると、その額はサービスの料金の中に出る。
料金の種類が`Fee`の行を「前払い」の列に移すよう、設定してある。
ただし`Fee`という値は、AWSの文書から取ったもので、実際の購入では確かめていない。

1. 買った月の請求が確定したら、ページでその額が「前払い」の列に入っているかを見る。
2. 「サーバー利用料」に入っていたら、その月の応答を手元で読み、前払いの行の`RECORD_TYPE`を確かめる。
   その値を`prepay`の`record_types`に足し、AWSから読み直す。
3. 必要なら`month_notes`にその月の注記を書く。

Savings Planの前払いは、実際の請求で確かめてある。

## Sponsorsへのリンクを出す

`config.json`の`sponsors_url`にSponsorsのページのURLを入れ、`fetch=false`で手で動かす。
`null`の間、リンクは出ない。

## 失敗したとき

| ログの内容 | 見るところ |
| --- | --- |
| `AWS has not finalized last month's costs` | AWSの請求の画面で、前月の請求書が出ているかを確かめる。出たあとに手で動かす |
| `Could not assume role with OIDC` | Environment `cost-report`のシークレットと、ロールの信頼関係のsubject |
| `Set the AWS_COST_REPORT_ROLE_ID secret` | Environment `cost-report`に、ロールのIDのシークレットがない |
| `aws ce get-cost-and-usage failed` | ロールの許可（`ce:GetCostAndUsage`）と、Cost Explorerが有効か |
| `the output contains an account ID or an ARN` | `config.json`に12桁の数字や`arn:`を書いていないか。公開を止めるための検査である |
| `income: …` | `cost-data`ブランチの`income.json`の、ログに出た月の書き方 |
| `Publish the page`だけが失敗 | 金額は保存済みである。`fetch=false`で手で動かせば載る |

取得やページの組み立てで失敗した実行は、ページも`costs.json`も変えない。
